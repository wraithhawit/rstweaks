RSTWEAKS / RSPERF - WHAT EACH VERSION DID
=========================================

One or two lines per version, newest first. This file is the short form; CHANGELOG.md is
the detailed history and carries the reasoning. BOTH ARE MAINTAINED - every version bump
gets an entry in each. CHANGELOG.md was backfilled to 0.2.80 on 2026-08-16; the only gap
left is 0.2.18 - 0.2.46, which was never written down anywhere and is recorded there as
one honest block rather than reconstructed.

The mod was called "rsperf" up to 0.2.40 and "rstweaks" from 0.2.41. Searching a log for
"rstweaks" will miss anyone still running an older build.

0.2.99
------
  Sophisticated Storage's failed-insert cache made able to hit. It remembers rejections
  by OBJECT IDENTITY, and RS builds a fresh ItemStack per attempt, so it never found its
  own entry and every attempt rescanned the whole barrel: 54% of the server thread on
  LavaSurf's profile, under one autocrafting task returning outputs. Second record keyed
  by item+components. Rejections only, per-tick, also cleared on any extraction - which
  upstream does not do. Config: cacheFailedInsertsByValue. Worth reporting upstream.

0.2.98
------
  BUG FIX: hard server crash on opening any grid or starting any autocraft, on a network
  whose cached total for one resource had overflowed past Long.MAX_VALUE and wrapped
  negative. MutableResourceListImpl.Entry.increment validates the amount being added and
  never the sum; it is the only unguarded route into that field. The total now saturates
  instead of wrapping, and is logged once per resource, naming the resource. Reported by
  LavaSurf 2026-08-18 (crash on the Step Requester, then on every grid open, surviving a
  relog). New gametest reproduces the exact crash with the clamp disabled.

0.2.97
------
  Two more plannerCheck scenarios (52 total), no behaviour change. 0.2.96 tested the
  BranchAndBound contract directly; these drive PlanMatrix with a starved budget on a graph
  known to plan, and assert on the literal "no integer solution" string that
  LpCraftingPlanner matches to set impossible. That coupling is what broke, and nothing was
  pinning it.

0.2.96
------
  BUG FIX: some late-game crafts could not be started at all -- Mekanism Teleportation
  Core and the ATM Star fragment recipe were the reported ones. The list preview said the
  craft was impossible and greyed out Start; switching the preview to TREE worked around
  it, because the tree preview is not hooked. Cause: the LP solver returned "no integer
  solution" when it had only hit its depth, node or pivot cap, and the preview treats that
  as proof. Budget exhaustion is now a decline, which falls through to stock RS.

0.2.95
------
  CORRECTION to 0.2.93's diagnosis, no behaviour change. The duplicate-task flood does NOT
  need a regulator upgrade, which is what 0.2.93 claimed. The common cause is the network
  not being able to craft as many as the exporter asks for: RS clamps the request to what
  is craftable now (say 1), and 1 never reaches the quota (say 64), so every following
  request starts another one-item task. Measured: 12 requests, 12 tasks, same resource, no
  regulator. `waitForRunningCraft` already fixed both; only the config text, the mixin
  comment and the tests were wrong about why.

0.2.94
------
  `/rstweaks stats` prints one counter per line under a header, instead of a dozen
  figures run together on one wrapping line. The periodic chat broadcast is now OFF by
  default (`chatNotificationIntervalSeconds` 0) and the join message no longer carries
  counters -- nothing posts them unprompted any more. Both at Wraith's request.
  The join line still announces version and active features.

0.2.93
------
  An autocrafting request waits for the craft already running for that resource (#14),
  behind `waitForRunningCraft` (default on). Stock RS only refuses a duplicate when the
  amount asked for is covered by what is running -- fine for a plain or tiered exporter,
  whose quota is a constant 1 or 64, but a REGULATOR upgrade asks for the whole
  outstanding shortfall, which grows as the destination drains, so every increase starts
  another task. Measured: 20 requests, 20 tasks for one resource. Now 1.

0.2.92
------
  Gametests for the paths that only fail in game, runnable without a human (issue #2).
  `./gradlew runGameTestServer` boots a dedicated server with Refined Storage staged in,
  runs six tests with our mixins applied and exits non-zero on failure, in about a minute.
  Covers a crafting task stepping and delivering its output, the Crafting Grid refill's
  two payment routes and its decline, and external extraction across a stale slot index.
  Each suite was confirmed to FAIL with the bug it targets put back.

UNRELEASED (in source, not yet in a built jar)
----------------------------------------------
  sparkProfile task. `./gradlew sparkProfile --args="<spark link|code|file>"` decodes a
  spark profile from the command line and ranks frames by share of the thread. A spark
  link is a protobuf payload on bytebin, not a web page.


0.2.91  BUG FIX - the phantom 0 row is preventSorting after all, the one field no probe ever
        printed. Latched, updateExisting takes a third arm that removes nothing. 0.2.86 fixed
        the wheel paths but assumed a held modifier is always released to the grid screen; the
        autocrafting preview opens over the grid and takes the key events, so it is not.
        containerTick now clears the flag whenever no modifier is held, healing a latch left
        by any route. (Issue #15)

0.2.90  DIAGNOSTIC - the 0.2.89 audit caught the phantom row and produced a contradiction:
        the row was logged REMOVED and survived anyway. That can only happen if Refined
        Storage never called ViewList.remove, i.e. the sticky check inside updateExisting
        answered differently from the same check outside it - which is what a @Redirect
        does, and Step Crafter ships one on exactly that call. This logs whether remove was
        called and what Step Crafter claims about the resource. (Issue #15)

0.2.89  DIAGNOSTIC - the 0.2.87 probe came back clean on a session that still showed the
        phantom 0 row, which rules out all three paths it watched. logGridViewDiagnostics
        now also audits the view list against the backing list after every update and every
        sort, reporting any row with nothing behind it, with a stack trace. Catches the bug
        whatever creates it. Changes no behaviour. (Issue #15)

0.2.88  BUG FIX - a worn tool's last few uses were stranded whenever the craft also had to
        make a replacement. One hammer with 3 uses left, 32 crafts asked for: the plan made
        a new hammer, took all 32 uses from it, and never touched the old one. The tool
        class is measured in uses, and netting production against consumption said the
        network owed nothing, so no hammer was requisitioned at all. It now asks for the
        uses it will burn, capped at what the network holds, most worn first. (Issue #10)

0.2.87  DIAGNOSTIC - 0.2.86 fixed a real stock-RS bug but NOT the reported one; the phantom
        0 row survived it. Adds logGridViewDiagnostics (default off), which restates Refined
        Storage's own DEBUG-level grid view logging at INFO and adds what the backing list
        holds after each change. Changes no behaviour. (Issue #15)

0.2.86  BUG FIX - a worn tool left a phantom row at 0 in the grid after every durability
        craft, cleared by tapping SHIFT and back on the next craft. Stock Refined Storage
        bug, reproducible without this mod: scrolling the grid with the wheel latches
        preventSorting on forever, and only a key release clears it, so any resource that
        hits zero keeps its row. We fix it because durability crafting retires a resource
        every craft and turns a rare wart into a constant one. Reported upstream.
        (Issue #15)

0.2.85  BUG FIX - fuzzy mode across DIFFERENT tools, the other half of #9. A fuzzy hammer
        slot demanded the copper hammer specifically and declared the craft impossible when
        you held the iron one. Tool grouping was splitting a class the graph had already
        unified; the uses of every tool a slot accepts now share one class. (Issue #9)

0.2.84  BUG FIX - durability crafting with fuzzy mode. Fuzzy replaced the encoded tool with
        the recipe's own ingredient items, which are always damage 0, while the byproduct
        kept the real damage - so a crystal at damage 50 read as "@0 in, @51 out" and one
        craft was costed at 51 uses. The encoded tool is now kept, first in the list.
        (Issue #9)

0.2.83  BUG FIX - the Max button ignored reusable tools, reporting 0 or a container count.
        RS reaches its calculator through three listeners and we hooked two; the max path
        was the third and never saw the planner. Now answered by it. Adds 17 headless
        checks for the search. (Issue #8)

0.2.82  BUG FIX - the gametest could never have found its template. It asked for
        "rstweaks:empty" while the file shipped under the pre-rename "rsperf" namespace,
        in duplicate, one of them in the 1.20 "structures" directory that 1.21 renamed to
        "structure". Now one file at data/rstweaks/structure/empty.nbt. (Issue #6)

0.2.81  Fluid substitution REMOVED - 26 files, ~3,600 lines. Use Ultramegaaa's "Refined
        Fluid Substitution" instead. The crafting-grid container refill survives and is
        unaffected; so does the LP planner's cycle handling, which recycled containers
        need regardless. rstweaks registers no content again.
        Gone from the config: fluidSubstitutionPatterns, reversibleFluidSwapPatterns,
        convertUnmarkedFluidPatterns. They can be deleted from rstweaks-common.toml.

0.2.80  Crafting-grid container refill no longer needs patterns or fluid substitution; the

0.2.79  Fluid substitution PARKED - Ultramegaaa's "Refined Fluid Substitution" covers it.

0.2.78  BUG FIX - putting a stored fluid pattern back in the grid wiped the Processing tab.

0.2.77  The Pattern Grid remembers which tab it was on, synced as an RS menu property. The

0.2.76  Diagnostics removed; the fluid tab's own matrix confirmed in game.

0.2.75  BUG FIX - Clear wiped the Processing matrix while on the fluid tab, leaving no way

0.2.71  DID NOT LAUNCH. The fluid tab gets its own matrix and a tab switch rebinds slots

0.2.70  Diagnostics removed; the mark confirmed working in game.

0.2.68  Diagnostic build, no behaviour change.

0.2.57  BUG FIX - durability duplication. A recipe burning two different durable tools

0.2.18 - 0.2.46  FLUID SUBSTITUTION (not individually recorded)
---------------------------------------------------------------
        Both records lapsed across this range and the per-version detail is gone. Fluid
        substitution was built here: the pattern type, the Pattern Grid tab and its 1-to-2
        layout, auto-fill, and reversible mirror patterns. Renamed rsperf -> rstweaks at
        0.2.41. See CHANGELOG.md for the fuller account of what is known.


0.2.17  Split the mixin configs so an absent optional mod (Step Crafter, Cable Tiers,
        Functional Storage) no longer takes every other optimization down with it. The
        startup and chat lines now list what is actually running.

0.2.16  Durability-aware planning. A tool that wears out is treated as a supply of uses,
        so one infusion crystal covers as many crafts as it has durability. Three parts:
        planner, storage scan, and an executor that ages what the pattern hands back.

0.2.15  The chat summary was suppressing itself - it decided whether to report from four
        counters while the body reported nine. All counters are deltas now.
        Added /rstweaks stats.

0.2.14  External storage stopped probing providers that cannot hold the resource type at
        all - an energy request no longer asks every item inventory in the network.
        Config: skipMismatchedStorageTypes.

0.2.13  The preview no longer doubles a self-duplicating craft (192 templates announced
        as 384).

0.2.12  Self-duplicating recipes work. Netherite templates consume what they produce, so
        the root pattern's outputs are now held in the task when it also consumes them.
        recycleRootByproducts renamed keepRecycledResourcesInTask.

0.2.11  The preview no longer claims to craft recycled containers. One bucket going round
        128 times is one bucket.

0.2.10  Fixed 0.2.9, which could not craft at all: Mixin does not search the hierarchy
        for shadowed fields, and the shadowed field was on the superclass.

0.2.9   Found why RS demands 64 buckets for 64 rice slimeballs - the executor, not the
        planner. Root byproducts now stay in the task.
        Config: recycleRootByproducts.

0.2.8   Fixed LP-planned crafts sitting forever. A cycle needs working capital: net
        consumption of zero and required capital of zero are different claims.
        Added the executability self-test and the headless runner.

0.2.7   An accepted LP plan logs the whole plan, not just its size.

0.2.6   RS's autocrafting DEBUG logging was 71.8% of the server thread - 209 MB of
        debug.log in 29 seconds. Raised that logger to INFO.
        Config: silenceAutocraftingDebugLog. Worth reporting upstream on its own.

0.2.5   The config file is readable: blank lines between entries.

0.2.4   lpPlanner defaulted to OFF after it broke crafting on a live server.

0.2.3   Slot index for external inventory extraction - 42.9 ms/tick, the single largest
        cost on a struggling server. The index only suggests slots; every one is re-read
        live. Config: externalStorageSlotIndex, externalIndexTtlTicks, minSlotsToIndex.

0.2.2   getSlots() no longer called once per slot while scanning external inventories.
        A 5,000-slot controller made 5,001 calls. ~6 ms/tick.

0.2.1   Drawer Controller connectivity check made O(1). Was 13.97% of the server thread,
        the largest single frame.

0.2.0   Version made visible at runtime. LP planner decline reasons split by cause, and
        infeasible plans name the blocking resource.

0.1.0   Everything up to and including the linear planner, shipped as one version across
        roughly eight builds - which is what prompted versioning at all.
        Measured: 5.29 -> 19.98 TPS.
